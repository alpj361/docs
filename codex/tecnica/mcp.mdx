## Endpoint público

```text
https://mcp.standatpd.com/mcp
```

El servidor usa MCP Streamable HTTP en modo stateless. Los mensajes JSON-RPC se envían mediante `POST /mcp`.

| Petición | Resultado esperado |
| --- | --- |
| `GET /mcp` | `405 Method not allowed` |
| `POST /mcp` sin sesión | `401` y desafío OAuth |
| `POST /mcp` autenticado | Respuesta MCP |

Un `405` al abrir la URL en el navegador no indica que el servidor esté caído. Un `404 Cannot POST /mcp` sí indica que la ruta no está registrada.

## OAuth

El servidor publica:

```text
/.well-known/oauth-authorization-server
/.well-known/oauth-protected-resource
/.well-known/oauth-protected-resource/mcp
/oauth/register
/oauth/authorize
/oauth/token
```

El flujo usa authorization code, PKCE y registro dinámico de cliente. El usuario inicia sesión mediante Pulse Journal y aprueba el acceso. El cliente recibe un access token de corta duración y puede rotarlo con refresh token.

## Herramienta `codex`

Acciones principales del contrato v4.1:

| Acción | Uso |
| --- | --- |
| `get_schema` | Obtener tipos, campos y presets del usuario |
| `resolve_field` | Buscar una definición equivalente |
| `create_field` | Crear un campo personal |
| `create_preset` | Crear un preset personal |
| `search_universe` | Resolver referencias antes de escribir |
| `create_universe_item` | Crear un ítem, auxiliar o Source permitido |
| `update_universe_item` | Actualizar por claves estables |

## Secuencia requerida

1. Ejecuta `get_schema`.
2. Busca el ítem antes de crearlo.
3. Ejecuta `resolve_field` antes de crear un campo.
4. Usa `create_field` solo con resultado `not_found`.
5. Escribe mediante `fields` y `preset_keys`.
6. Corrige shapes usando `details.correction`.

```json
{
  "action": "create_universe_item",
  "tipo": "Actor",
  "name": "Nombre del actor",
  "fields": {
    "sys_actor_cargo": "Diputado",
    "sys_actor_eje_social": { "value": -10 }
  },
  "preset_keys": ["sys_base_actor"]
}
```

## Reglas para agentes

- No inventes UUIDs. Obtén cada referencia de una búsqueda previa.
- No crees sinónimos cuando el catálogo ya contiene el concepto.
- `flag` fue eliminado. Usa campos `eje` con polos declarados en el schema.
- `archivo` e `imagen` reciben referencias del Codex, no URLs libres.
- `Source` es un ítem oficial y puede citarse o relacionarse.
- `Post` y `Snippet` son auxiliares, aunque conserven `tipo`.
- Un Perfil se crea como `Actor` con `is_profile = true`.
- Cada operación se ejecuta con el usuario autenticado y no puede acceder a registros ajenos.

## Simulaciones agentic

La herramienta de simulación conserva el ciclo `crear` → `actuar` → `reporte`. El backend persiste la ejecución para que pueda consultarse después de un reinicio.

El agente debe:

1. identificar qué participantes son actores reales, perfiles guardados o sintéticos;
2. enlazar Sources y contexto mediante UUIDs verificados;
3. completar todos los turnos indicados por el servidor;
4. redactar conclusiones solo después de obtener el reporte;
5. presentar resultados como simulados, con supuestos e incertidumbres.

## Geografía

El MCP debe distinguir `frontier`, área personalizada y punto/POI. Una coordenada no convierte por sí sola un Territorio en frontera. Consulta [Geografía y territorios](/codex/tecnica/geografia-y-territorios) antes de escribir shapes.
