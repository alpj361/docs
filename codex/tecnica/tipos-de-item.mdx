El schema v4.1 publica cuatro listas distintas. No las combines en un único enum de interfaz.

## Ítems oficiales

| Tipo persistido | Representa |
| --- | --- |
| `Actor` | Persona o individuo real |
| `Entidad` | Organización, institución, empresa, partido o colectivo |
| `Territorio` | Lugar, punto, área o frontera geográfica |
| `Evento` | Suceso situado en el tiempo |
| `Historia` | Narrativa, investigación, caso, ley o marco de análisis |
| `Objeto` | Evidencia, documento, dataset u objeto concreto |
| `Artefacto` | Sistema, herramienta, método o infraestructura |
| `Source` | Origen consultable y citable de información |

Estos valores aparecen en `itemTypes` y tienen `typeClass = official_item`.

`Source` comparte el núcleo de un ítem oficial, pero su metadata de presentación indica tarjeta y modales propios, con `primaryAction = cite`.

## Tipos auxiliares

| Tipo persistido | Uso |
| --- | --- |
| `Post` | Publicación capturada desde una plataforma |
| `Snippet` | Nota, cita o fragmento interno |

Ambos aparecen en `auxiliaryTypes`. Siguen identificándose mediante `tipo` y forman parte de `storageTypes`, pero no deben contarse ni presentarse como ítems oficiales del universo.

## Perfiles

`Perfil` no aparece en las listas de tipos. Es una modalidad de Actor:

```json
{
  "tipo": "Actor",
  "is_profile": true
}
```

Representa un tipo de persona o grupo. No corresponde a una persona real. El preset `sys_profile_actor` se aplica únicamente cuando `is_profile` es verdadero.

## Recursos

`Simulacion` aparece en `resourceTypes`. Tiene `typeClass = resource` y `storedInTipo = false`. Su ejecución vive en tablas operativas separadas.

## Aliases vigentes

| Entrada antigua | Tipo actual |
| --- | --- |
| `Evidencia` | `Objeto` |
| `Biblioteca` | `Historia` |
| `Fuente` | `Source` |

El cliente puede traducir labels para el usuario, pero debe persistir el valor canónico devuelto por el schema.

<Warning>
  Documentación anterior listaba nueve tipos canónicos incluyendo Post y Snippet. Ese modelo quedó obsoleto en v4.1.
</Warning>
